# Проверка Vega и TShock 6.2.1 от 27 ноября 2026 года

Администраторские скрипты TShock пока требуют адаптации. Самые заметные расхождения в этом прогоне затрагивают переименование групп, работу с несколькими правами, чтение свойств группы и команды, доступные из консоли.

Сравнивались Release-сборка Vega `a699624d` с локальным исправлением генерации мира (Terraria 1.4.6.1, протокол 329) и официальный TShock 6.2.1 (Terraria 1.4.5.8, протокол 326). Для проверки команд серверы стартовали на loopback с отдельными копиями миров подходящей версии и отдельными базами. В качестве второго справочника для пакетов использовался форк TerraZ `81175b93`. [Официальный исходный код TShock](https://github.com/Pryaxis/TShock/tree/b25b3e5bf59870e08175a33df3f8a9c7fc9958c1/TShockAPI)

## Команды и подкоманды

На **каждом** сервере выполнено 475 консольных проверок. В их число вошли запросы справки по 95 основным именам и 27 алиасам, вызовы всех 95 основных команд, включая оба варианта остановки в разных процессах, 212 проб подкоманд и именованных аргументов, а также 46 шагов сценариев. Последние включают случаи, когда результат одной команды читали следующей. [Ввод и ответы обоих серверов](tshock-check-2026-11-27-commands.csv)

В консоли Vega справка открылась для 70 из 95 основных имён и для 87 из 122 имён с учётом алиасов. В TShock консоль показала справку для всех 122. Из 25 остальных основных имён Vega 23 имеют регистрацию для игрока, а `su` и `sudo` отсутствуют. Консольная справка TShock также описывает команды, которые затем требуют входа в игру. [Реестр команд, синтаксис и права](tshock-command-parity-2026-11-27.md)

Два дополнительных клиента подключились по TCP к каждому серверу, получили секции карты и вошли в мир в отдельных прогонах. Гость отправил **32 команды**. Администратор авторизовался через `/login` и отправил **146 команд**. В игровом чате администратора справка Vega разрешила **120 из 122** имён TShock, включая все 27 алиасов. Оставшиеся два — `su` и `sudo`. TShock показал справку для всех 122. Обе системы подтвердили телепорт по координатам, выдачу одного блока земли, применение баффа, вызов Глаза Ктулху и отключение входящих телепортов. Гостю Vega разрешила `/version`, TShock отказал. Вывод `/playing` также различается. Строки `chat-guest` и `chat-admin` в CSV содержат ответы, полученные клиентом по сети.

В игровом `/ui AuditPlayer` обе системы показали IP тестового подключения, имя учётной записи и группу. Vega дополнительно показала короткий UUID и `Platform: Unknown` при отсутствии сведений от клиента. В отдельном входе по протоколу 329 клиент передал штатный `PlayerPlatformInfo` с платформой Steam, после чего `/ui` вернула **`Platform: PC`**. TShock сравнивался в базовой комплектации без расширения TSExt_UICommand.

| Проверенный сценарий | Vega | TShock 6.2.1 |
|---|---|---|
| `group rename auditrole auditnew`, затем `group list` | Показывает справку, в списке остаётся `auditrole` | В списке появляется `auditnew`, старое имя исчезает |
| `group addperm auditrole audit.read audit.write`, затем `listperm` | Отказывает в вызове с двумя правами, список остаётся пустым | Добавляет оба права. Аналогичный вызов `delperm` удаляет оба |
| `group prefix`, `suffix`, `color` с именем группы, без нового значения | Возвращает справку. Свойства видны в `group listperm` | Показывает запрошенное значение |
| `group color` с `101,102,103`, затем отдельная проба с `00ff00` | Принимает оба формата | Принимает RGB, отклоняет HEX |
| `rest listusers` | Считает настроенные операторские токены | Показывает активных REST-пользователей. Во время проверки список был пуст |
| `me`, `reply`, `whisper` из консоли | Требуют игрока | Обрабатывают консольный вызов |
| `tileban` и `projban`, цикл `add 1 → list → del 1 → list` | ID появляется и исчезает | Такое же изменение списка |
| `time noon`, затем `time` | Возвращает 12:00 | Возвращает 12:00 |

212 проб охватывают литералы из обработчиков и вложенных веток, в том числе типы боссов, направления расширения регионов, варианты событий мира и фейерверков. Часть вводов проверяет только диагностику аргументов или требование игрового контекста. Например, вызов `firework red` из консоли не проверяет цвет фейерверка у игрока. В CSV сохранены фактические ответы, включая вывод ошибок. Знак «—» означает, что в отведённом окне отсутствовал содержательный ответ. Длинные ответы сокращены.

## Обработка пакетов

В живом сетевом сценарии клиент обеих версий прошёл выдачу слота и ввод пароля, отправил описание персонажа, UUID, здоровье, ману, запрос мира, запрос секции и появление игрока. Обе версии передали секции карты, приняли команды через `NetTextModule` и вернули ответы по TCP. Для Vega пароль запрашивался перед выдачей слота, для TShock в конфигурации стенда — после неё. Это подтверждает обычный путь входа тестового клиента. Полный цикл SSC с выходом, повторным входом и переносом персонажа между мирами этим сценарием не покрыт.

В официальном `GetDataHandlers` зарегистрировано **72** типа пакетов, в TerraZ **71**. Общих типов 69, в объединении 74. Для каждого официального типа проверено совпадение числового ID в сборках TShock и Multiplicity, используемой Vega. Для каждой строки приведены обработчики обеих версий, семейство в Vega, известный путь обработки и связанные успешно выполненные наборы тестов. Число в скобках относится ко всему набору. `Other` — значение классификатора Vega. Например, для `ContinueConnecting2` отдельно работает проверка допуска в мир. [Матрица всех 74 типов](tshock-check-2026-11-27-packets.csv)

В матрице имена обработчиков получены из двух зафиксированных ревизий TShock, семейства — из текущего классификатора Vega, результаты тестов — из TRX этого прогона. Описания для 71 типа TerraZ взяты из предыдущего аудита, для трёх дополнительных типов официальный код и маршруты Vega проверены отдельно. Отдельного клиентского сценария с проверкой конечного состояния для каждой из 74 строк в этом прогоне не было. [Исходный аудит поведения](server-behavior-audit.md)

| Типы | Результат |
|---|---|
| `ItemOwner` (22) | Есть в официальном реестре. TShock использует обработчик в том числе для перехода состояния SSC. В Vega найден контроль готовности игрока. Эквивалентность перехода SSC по этому пакету остаётся открытой |
| `SyncRevengeMarker` (126) | Официальный обработчик читает маркер и передаёт управление ванильной логике. Отдельная политика Vega в исходниках не найдена. Конечное состояние маркера в двух мирах не сравнивалось |
| `SyncChestSize` (155) | Есть в официальном реестре. В Vega найдены проверки размера, полномочий на работу с сундуком, ограничений региона и виртуальных сундуков. Прошли связанные тесты хуков и проверки изменения мира |
| `SyncCavernMonsterType` (136), `SpectatePlayer` (150) | Из двух реестров отдельные обработчики есть только в TerraZ. В Vega для первого используется ванильная синхронизация, второй входит в семейство `PlayerState` |

## Тесты и нагрузка

- В Release прошли **33 архитектурных и 944 runtime-теста**, падений 0. Пропущены 8 интеграционных кейсов с внешними MySQL/PostgreSQL. Запуск включал проверки владения пакетами, частоты пакетов, инвентаря, SSC, регионов и PvP.
- На развёрнутой сборке Vega прошли проверки REST с чтением и изменением мира, экспорта схемы, TCP-доставки, изоляции песочниц с общим хранилищем допуска, команд групп, регионов, ограничений контента и событий мира.
- Микротест Vega обработал 1 024 000 `PlayerUpdate` для 200 модельных сессий с проверкой отправителя и учётом метаданных. Получено 2,88 млн пакетов/с, 0,032 байта выделений на пакет, сборок GC за интервал измерения 0. Это скорость соответствующего участка входящего конвейера в памяти.

В отдельном синтетическом прогоне оба сервера получили копию одного мира, 300 тиков прогрева и 600 измеряемых тиков. Стенд создал 255 игровых слотов, выполнил 25 500 обновлений движения, 5 100 ударов и 1 275 сообщений. На обеих сторонах подтверждены 600 обновлений мира и контрольные суммы вывода для 255 loopback-получателей.

| Метрика одного прогона | Vega, ordered TCP с пакетной отправкой | TShock 6.2.1, тестовый транспорт |
|---|---:|---:|
| Время 600 тиков | 10,94 с | 106,34 с |
| Средняя частота за интервал | 54,8 TPS | 5,6 TPS |
| Интервал между тиками, p95 | 22,19 мс | 200,88 мс |
| Интервал между тиками, p99 | 25,08 мс | 233,48 мс |

Vega в этом прогоне не удержала бюджет 16,67 мс на тик. У TShock записан результат всех 600 тиков, но при завершении стенда процесс аварийно завершился с `NullReferenceException` в `Terraria.Netplay.UpdateConnectedClients`. Это наблюдалось в процессе с тестовым плагином и синтетическими слотами. Различаются версии движка и транспортные реализации стендов. Прогоны по одному разу не позволяют переносить отношение TPS на живой сервер.
