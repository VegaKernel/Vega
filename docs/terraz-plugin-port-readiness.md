# TerraZ plugin migration readiness

This describes the available Vega SDK, not a promise that existing TShock assemblies load unchanged. Port the TShock integration layer; keep the plugin's domain model, configuration, commands and storage migration as appropriate.

| Priority / plugin family | Vega surface | Remaining integration work |
| --- | --- | --- |
| P0 — ChatGuard, BadPig, Clans | `Commands.Snapshot`, `Activity.BeforePlayerCommand`, `BeforePublicChat`, completion and accepted-chat observations | Pre-command policy sees the authorized command name and exact session, not arguments or credentials; no arbitrary impersonation or command replacement. |
| P0 — RegionExt, HouseRegions, WorldScene | `World.Regions`: versioned CRUD, ACLs and flags; `WorldEvents.OnRegionEntered/Left/Changed`, typed tile interaction and PvP/team intentions with deny-only policies | Membership is tick-observed; the authoritative action still passes all built-in checks. Accepted native player interactions also expose bounded before/after cell observations; global framing and object changes are not a complete history. |
| P0 — Donations, Telegram audit, ControlGroupOption | `Identity`: account/group reads, committed mutations, delegated role assignments and own temporary leases | Explicit operator-selected assignment groups; no raw credentials, unrestricted group-permission mutation or cross-process event replication. |
| P0 — WalletService, TelegramBot, RegionExt.Requests | `Services` versioned typed contracts and `Data` isolated durable document operations with CAS/batch transactions | Port old relational schemas explicitly. Services are local to the server process; no arbitrary SQL connection access. |
| P0/P1 — SessionTracker, RolePlay, SurvivalStages, PlayTimeRewards | Post-tick vitals and progression; native NPC/projectile events and completed native player hurt observations with victim session, actual damage and provenance | Confirmed native melee context is distinguished from unverified/client-reported sources; not all PvP damage is server-simulated. |
| P1 — WorldEdit, History | Exact tile compare/apply and bounded `UndoAsync` receipt, redo, native tile synchronization and `OnPlayerTileChangesCommitted` | Bounded (4,096-cell) observations of actual native differences; composite objects/chests/NPCs, out-of-range effects and natural simulation are not fully attributed. |
| P1 — NPCShop, WalletService | Explicit external NPC wallet provider registration with existing reservation/SSC/finalization protocol | Provider must implement its durable reservation contract, with stable operation IDs; pending purchases require the same provider after restart. |
| P1 — TelegramBot, REST integrations | Plugin-owned typed queries/actions under the authenticated administrator-only loopback `/v1/plugins/` namespace | Migrate external clients to the typed route contracts. No raw server, arbitrary headers or authentication material. |
| P1 — CustomItems, ItemChanger | `Players.Actions.CustomItems` activation-owned named recipes, transient world-item stats and persistent virtual item instances with immutable versioned recipes, CAS transfer and revoke | Physical arbitrary stat identity across inventory/SSC/trade and projectile/ammunition overrides still require a separate authoritative inventory model. |
| P1 — FakeProvider, Region-Vision, LobbyVisuals, MiniLobby | Virtual overlays and objects, `TileUiLayout` and scoped `TileUiPanel` with nested bounded layouts, labels, buttons, draggables and stock WireKite gestures | Complete legacy TUI widget library and real-client timing tests remain open. |
| P1 — LobbyServer, inter-server plugins | Authenticated optional peer transport, `plugin.Cluster` typed notifications, direct sends, broadcast, role/capacity presence and advisory routing | Independent-server player transfer and distributed SSC authority remain open; no remote command execution. |
| Built-in — Homes | `/sethome`, `/myhome`, `/delhome`, numeric limits, transactional three-provider persistence and offline import | The operator maps legacy numeric world ID to the actual target file GUID. |

See [Homes](player-homes.md), [identity](plugin-identity-sdk.md), [regions](plugin-region-sdk.md), [world editing](plugin-world-edit-sdk.md), [services and data](plugin-services-data.md), [custom NPCs](custom-npcs.md), [REST](plugin-rest.md), [FakeProvider buttons](plugin-fakeprovider-buttons.md), [gestures](plugin-fakeprovider-gestures.md) and the general [plugin SDK](plugin-sdk.md).

The [plugin cluster transport](plugin-cluster.md) is tested between real loopback listeners. LobbyServer still needs actual connection/transfer admission and distributed SSC ownership and qualification across independently deployed servers; the existing shared whitelist and ban paths remain independent of plugin notifications.
