# Vega server command audit

This is the Phase 25 command sub-ledger referenced by `server-behavior-audit.md`.

Pinned source: `TerraZ-Team/TShock` `general-devel@81175b934497f9ef0ee5b5200334e4260b0cc06c`, `TShockAPI/Commands.cs::InitCommands`.

The pinned registry contains exactly 95 built-in `Command` registrations. Every registration stays visible until its method branches are reviewed and assigned `Vega built-in`, `Terraria native passthrough`, `Optional module` or `Drop`.

`Pending` is not a decision. It means the row is inventoried but the corresponding method/side-effect audit is still open.

Checkpoint (2026-11-26): 92 of the 95 historical registry rows now have a Vega implementation, implemented slice or operator alternative; `rocket` has a conditional implementation but native SSC is available in opted-in authoritative worlds; `su` and `sudo` are deliberate compatibility omissions with an audited alternative. All 95 registry rows now have a decision. This counts command coverage, not complete branch/protocol equivalence with TShock. Live-client confirmation, live SSC lifecycle qualification, remaining REST write endpoints, and original command semantics remain separate acceptance gates.

## Completion rule

### Current native runtime implementation coverage

An `Open` row above does not necessarily mean no Vega command exists. The following
existing verticals also ship in the patched 1.4.6.1 server, but their original TShock
method branches still require an explicit semantic audit:

- `user`/`account`, `register`, `login`, `logout`, `password`, `group`, `region`, `ban`, `kick`, `mute`/`unmute`, `userinfo`, `playing`, `help`, `aliases`, `checkupdates`, `serverinfo`, `save`, and `shutdown` (`off`, `stop`). Their handlers and existing account, command, region and moderation tests are available in the repository.
- Temporary account roles exist as `account temp`, `account temp-clear`, `account temp-list`; the independent TShock `tempgroup` semantics are not audited yet.
- Configuration validation exists as `config validate`; `reload`/`config reload` refresh deployment-wide whitelist and world-local content restrictions/build protection independently. Listener and world startup configuration remains restart-only.

Private/team chat is now available through `whisper`/`w`/`tell`/`pm`/`dm`, `reply`/`r`,
`wallow`/`wa`, `party`/`p`, and `me`. Permission checks, mute moderation, same-world
recipient selection, team filtering, session-bound delivery and disconnect cleanup are tested
by `PlayerChatCommandsTests`; server-console whisper/reply and live clients remain open.

`antibuild [on|off|status]` and `protectspawn [on|off|status|radius <1..500>]` now persist
world-local settings and are evaluated before region authorization. Distinct global/spawn
bypass rights and a live spawn position are tested by `RegionBuildAuthorizationPolicyTests`.
Client reconciliation and the complete original protection behavior remain open.

Additional native world commands now available: `worldmode`, `spawnrate`, `maxspawns`,
`setspawn`, `setdungeon`, `forcehalloween`, `forcexmas`, `clearangler`; `worldevent`
also supports native moon events, slime rain, sandstorm and vanilla-condition invasion
start. `spawnboss`/`sb` delegates to the native summon path; `butcher` uses native
combat with conservative boss/town-NPC protection; `renamenpc` targets active town NPCs.
Native counters support `death`, `pvpdeath`, `alldeath`, `allpvpdeath` for current online
players; `motd`, `rules`, and `version` are also registered. Exact legacy branches,
client synchronization and historical account rankings remain open.

The next high-value gaps are full primary-world SSC authority and initial authentication,
remaining NPC/boss/event branches, player lifecycle
and character administration, configuration management, and additional content policy
branches. These must be validated against 1.4.6.1 live clients as well as the historical
command inventory. The native two-process smoke test covers world materialization,
readiness and graceful shutdown, not those gameplay branches.

Inventory completion is not semantic completion. Every `Pending` field must be resolved by reviewing the pinned handler method and comparing its behavior with Vega and the pinned Terraria 1.4.5.8 server. Intentional omissions require an operator-visible `Drop` rationale.
